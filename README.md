# 转发拆解 · cortico-world-forward-reader

给 [Coopanion](https://github.com/Pal-AI-Lab/Coopanion) 的 Coo 一个工具：把 QQ 的「合并转发 / 聊天记录」一层层拆到底。

> **前置：先装「QQ群聊插件」。** 这个 World 自己不连 QQ，也不存 QQ 的连接信息——它借 QQ群聊插件配好的那套东西干活：
> SnowLuma 的 OneBot HTTP 接口用来取消息，插件里配的视觉端点用来识图。
> 没装那个插件，这里两个工具都只会回「连不上」。

Coopanion 自带的消息展开只摊开一层，转发里套着的转发看不见。这个 World 借本机 SnowLuma 的 OneBot HTTP 接口递归调 `get_forward_msg`，把整棵树拉出来，按「谁 · 什么时候 · 说了什么」列成带缩进的文字。

**只读**：只调 `get_login_info` / `get_msg` / `get_forward_msg`，不发消息、不改配置、不写任何东西。

## 两个工具

| 工具 | 作用 |
|---|---|
| `qq_forward_read` | 拆一条合并转发（可嵌套）。参数：`ref`（消息编号，行首 `#` 后面那串数字）、可选 `maxChars` / `depth` |
| `qq_forward_status` | 自检：接口地址、SnowLuma 配置路径、token 有没有、能不能登录 |

输出长这样：

```
[张三 11-02 22:31] 你们看这个
  —— 又一层（共 3 条）——
  [李四 11-02 22:29] 哈哈哈哈
  [王五 11-02 22:30] 真的假的
```

## 前置

- 装了 **QQ群聊插件（qqbot）**：SnowLuma 连接、OneBot 地址、视觉端点都在它那儿配。
- 装了 **SnowLuma**（OneBot v11 实现），HTTP 接口开着，默认 `127.0.0.1:3000`。
- OneBot 配置文件里有 `accessToken`。默认读 `D:/snowluma/config/onebot_<QQ号>.json`，也可以在配置页手填路径或直接填地址和 token。

## 图片（默认当附件交出去）

拆到图片时，图会被下载下来、作为**附件**跟回执一起交给模型。

- 能看图的模型（主模型支持图片）就直接看到图，不用多花一次调用。
- 看不见图的模型只会收到一行文字说明（谁、什么时候、链接），不会因为带图出错。
- 一次最多贴 `attachMax` 张（默认 6），单张超过 `attachMaxMb`（默认 8 MB）就跳过，正文里仍然有链接。
- 不想贴附件，把「把图片当附件一起交出去」关掉，就退回只给链接。

## 识图（只在要文字描述时才跑）

附件之外还想要一句**文字描述**时，在调用时传 `captions: true`——**没有开关会自动识图**，因为图已经当附件交给模型了，再识一遍是白花钱。

- 端点默认**跟着 QQ群聊插件走**：那边配好了视觉端点、模型、key，这里就自动认得到，不用再填一遍。
- 配置页里**没有**端点/模型/密钥这几格；那边没配，识图就只会写一句「没找到视觉端点」。
- 它只对**看不见图的模型**有用（纯文字模型只会读到一行「谁、什么时候、一张图、链接」），能看图的模型用不上。
- 一张图一次调用，会花钱，所以不传就不跑。
- 识图失败不会弄坏整份拆解，只会在那张图后面写一句失败原因。


## 配置项

- SnowLuma 配置路径（默认 `D:/snowluma/config/onebot_<QQ号>.json`）
- OneBot 接口地址（默认 `http://127.0.0.1:3000`，留空用配置文件里的 host/port）
- accessToken（一般留空，从配置文件读）
- 嵌套层数上限（默认 8）
- 回执字数上限（默认 12000）
- 请求超时（默认 15000 ms）
- 把图片当附件一起交出去（默认开）、一次最多处理几张（默认 6，附件和识图共用）、单张上限 MB（默认 8）
- 识图：每句描述字数（不传 `captions: true` 就不会跑；端点自动跟着 QQ群聊插件走，不单独配）

## 限制

- 没有 SnowLuma / OneBot HTTP 接口开着，工具只会报「连不上」。
- 只能读本 bot 在 QQ 上收到过的消息；别人的私聊翻不到。
- 回执超字数会截断，最后一层可能不完整。
